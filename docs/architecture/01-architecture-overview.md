## 1. Purpose and scope

This document is the Architecture Definition baseline for the Meldra Grid
Data Platform: an Apache Iceberg lakehouse, catalog and analytical query
layer intended for regulated utility operators — electricity distribution
and transmission, gas networks, oil and gas midstream, water, and metering
service providers.

It covers Business, Data, Application and Technology architecture, and
records where the current implementation is **compliant**, **partial**, or
**not yet built**. That distinction is deliberate and is maintained
throughout: an architecture document that describes intent as though it
were state is worse than no document, because it will be relied on during
procurement and assurance.

**In scope:** the lakehouse, catalog, RBAC and tenancy model, query
engine, agentic interface, audit trail.

**Out of scope of this baseline:** the Energy Trust Protocol (ETP) itself,
which is a distinct edge/transport-layer product with its own
specification. ETP's *integration contract* with this platform is defined
in §7; ETP's internal design is not described here.

## 3. Architecture principles

These are the decision rules. Where a design choice in this repository
conflicts with one, that conflict is recorded as a gap in
[06-gap-analysis.md](06-gap-analysis.md) rather than quietly tolerated.

| # | Principle | Rationale | Implication |
|---|---|---|---|
| **P1** | **Fail closed.** Any component that cannot determine authorisation refuses the request. | A grid platform's failure mode must be unavailability, never disclosure. | `rbac_is_noop()` returns `False` on policy-store error; `assert_tenant_scoped()` defaults to enforced in production. |
| **P2** | **Isolation is structural, not procedural.** A tenant boundary that depends on a caller remembering to pass a parameter is not a boundary. | SEC-2026-001 was exactly this failure. | Context-bound tenant binding; AST test enforcing it in CI. |
| **P3** | **Open table formats, no lock-in.** Iceberg on object storage; no proprietary storage layer. | Utilities run 20–40 year asset lifecycles and will outlive any vendor. | Data remains readable by Spark, Trino, Dremio, Snowflake, DuckDB without Meldra. |
| **P4** | **Determinism where money and safety live.** Settlement, billing and protection calculations are computed by the query engine, never generated by a language model. | A hallucinated settlement figure is a regulatory event. | The agent emits SQL; Iceberg and DuckDB compute the numbers. See [ADR-0003](../adr/ADR-0003-llm-boundary.md). |
| **P5** | **Every decision is auditable.** Read, deny and error events are recorded with UTC timestamps and actor identity. | NIS Reg. 10; NCSC CAF C1; SEC obligations. | `observability/audit_log.py`, JSON-lines, append-only. |
| **P6** | **Data minimisation at the boundary.** Nothing leaves the trust boundary that does not need to. | UK GDPR Art. 5(1)(c); consumption data reveals occupancy. | Inference egress is the platform's largest open gap — see §6 and [GAP-01](06-gap-analysis.md). |
| **P7** | **Claims must be true.** No function reports success for work it did not do; no document describes intent as state. | `expire_snapshots()` previously returned "Expired older snapshots…" from a body containing `pass`. | Honest docstrings; gap register; status labels on every capability. |

## 4. Architecture Vision (ADM Phase A)

**Vision statement.** A utility operator can ask a question of decades of
metering, SCADA and asset data in plain language, get an answer that is
provably derived from immutable, lineage-tracked records, and hand the
audit trail to a regulator without further work.

**The problem being solved.** Grid data is high-volume, high-cardinality
and long-retention. A single DNO with 3 million smart meters at half-hourly
granularity generates roughly **52.6 billion readings per year**
(3e6 × 48 × 365). Retention obligations are measured in years. Traditional
warehouses price this out; raw object storage makes it unqueryable;
Hadoop-era lakes make it ungoverned. Iceberg's manifest-based pruning,
schema evolution and snapshot isolation are the correct primitives, but
they are not a product on their own.

**What Meldra adds:** governed multi-tenancy, role-aware data-layer
masking, a natural-language interface bounded to deterministic execution,
and an audit trail designed for the regulator rather than for the operator.

### 5.2 The Policy Enforcement Point

The single most important structural property of this architecture: **RBAC
is applied to the data, before it reaches any execution engine.**

`enforce_rbac()` masks, filters and denies at the DataFrame/Arrow layer.
Only then is the relation registered with DuckDB. This means column
aliasing, subquery wrapping, `SELECT *`, CTEs and view tricks cannot
recover a masked value — the value is not present in the registered
relation. Compare the common alternative of rewriting the user's SQL to add
predicates, which is defeated by any sufficiently creative query.

The zero-copy fast path added in PERF-2026-003 preserves this property:
`rbac_is_noop()` still calls `check_table_access()`, and returns `False`
whenever *any* policy applies or the policy store is unreachable. The fast
path is taken only when enforcement would provably be a no-op.

## 6. The critical open item: inference egress

Principle P6 is not currently met. Agent reasoning calls an external
inference endpoint (`api.anthropic.com`). For an operator inside NIS
Regulations scope, or a DCC-connected party under the Smart Energy Code,
sending metering or operational telemetry to a third-party endpoint is
generally a blocking control failure regardless of contractual terms.

This is the difference between a platform that demos well and one that can
be deployed. It is tracked as [GAP-01](06-gap-analysis.md) with three
viable resolutions (in-region managed inference, private VPC deployment,
or a redaction gateway ahead of IF-07). It should be resolved before any
regulated pilot, not during one.

## 7. ETP integration contract

The Energy Trust Protocol operates at the meter and transport edge. This
platform operates at rest and at query time. They are complementary layers
with a defined seam, and conflating them weakens both.

| Concern | Owner | Why |
|---|---|---|
| Reading integrity at origin | ETP | Block-native structure, tamper-evidence at the meter |
| Attacker deception and profiling | ETP | Phantom Grid |
| Attack-surface rotation | ETP | Moving Target Defence |
| Anomaly detection on the wire | ETP | AI Sentinel |
| **Verified reading → durable record** | **Seam** | ETP block hash is written as an Iceberg column |
| Retention, time travel, replay | This platform | Iceberg snapshots and manifests |
| Query-time authorisation | This platform | Policy Enforcement Point |
| Audit trail for the regulator | This platform | `audit_log` + Iceberg snapshot history |

**Contract requirement.** Ingest must persist the ETP block hash and
verification status as first-class columns
(`etp_block_hash`, `etp_verified_at`, `etp_sentinel_score`) so that any
row returned by a query can be traced back to a verified reading. Without
this, ETP's tamper-evidence stops at the lakehouse boundary and the
end-to-end trust claim cannot be substantiated. Not yet implemented —
[GAP-07](06-gap-analysis.md).

**What this platform must not claim.** Zero-copy analytics do not provide
tamper-evidence, and the ephemeral session model does not provide an audit
trail. Those are ETP's and Iceberg's jobs respectively. Marketing that
merges the three will not survive a technical due-diligence review.
